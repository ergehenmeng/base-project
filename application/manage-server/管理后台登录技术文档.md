# 管理后台登录技术文档

## 1. 系统概述

管理后台登录系统基于 `manage-server` 应用模块和 `platform-iam` 平台模块构建，提供账号密码登录、短信验证码登录两种方式，并支持 TOTP 双因子认证（2FA）、登录安全防护（账号/IP锁定、异地登录检测）、RSA 密码加密传输等安全机制。

### 核心模块

| 模块 | 路径 | 职责 |
|------|------|------|
| manage-server | `application/manage-server` | 登录接口入口、认证过滤器、权限拦截器 |
| platform-iam | `platform/platform-iam` | 用户服务、Token服务、登录安全服务、登录缓存管理 |
| base-core | `foundation/base-core` | 通用配置、枚举、安全上下文、注解定义 |
| base-web | `foundation/base-web` | Web层工具类、限流切面 |

### 2.1 账号密码登录流程

```

 │                          │──verifyCodeError()────>│(图形验证码校验)              │                            │                            │
 │                          │──checkLoginType()────>│(登录方式校验)                │                            │                            │
 │                          │──login()─────────────>│                            │                            │                            │

 │                          │                            │──checkIpNotLocked()─────>│                            │                            │
 │                          │                            │──getByAccount()────────>│(查询用户)                   │                            │
 │                          │                            │──encoder.match()────────>│(密码校验)                   │                            │
 │                          │                            │──checkGeoChange()──────>│                            │──>│(异地登录检测)             │
 │                          │                            │                            │                            │                            │

 │                          │                            │──是──>needTotp()/needBindTotp()                     │                            │

 │                          │                            │                            │                            │               createToken() │
 │<──TotpLoginResponse────│                            │                            │                            │                            │
```

### 2.2 登录状态码（TotpLoginResponse.state）

| state | 含义 | 前端处理 |
|-------|------|----------|
| 1 | 登录成功 | 直接获取 `data` 中的 `LoginResponse`，跳转首页 |
| 2 | 需要输入双因子校验码 | 弹出 TOTP 验证码输入框，携带 `uuid` 调用 `/manage/checkTotp` |
| 3 | 用户尚未绑定双因子 | 展示 `qrcode` 二维码让用户扫码绑定，绑定后调用 `/manage/bindTotp` |

### 2.3 短信验证码登录流程

```
① POST /manage/sendSms   →  校验图形验证码 → 校验登录方式 → 发送短信验证码
② POST /manage/smsLogin  →  校验登录方式 → 验证短信验证码 → 校验用户状态 → 执行登录
```

### 2.4 TOTP 双因子验证流程

**校验双因子：** `POST /manage/checkTotp`
- 前端携带 `uuid`（登录时返回）和 `verifyCode`（用户输入的6位动态口令）
- 后端根据 `uuid` 从缓存获取 `userId`，校验 TOTP 验证码是否正确
- 校验通过后执行登录，清除 TOTP 缓存

**绑定双因子：** `POST /manage/bindTotp`
- 前端携带 `uuid`、`secretKey`（登录时返回）、`verifyCode`（用户扫码后输入的6位动态口令）
- 后端校验验证码正确后，将 `secretKey` 持久化到 `sys_user.totp_secret`
- 绑定成功后执行登录

## 5. 认证与鉴权机制

### 5.1 Token 创建

系统支持两种 Token 实现，通过配置 `application.manage.token.token-type` 切换：

| 类型 | 配置值 | 实现类 | 说明 |
|------|--------|--------|------|
| Redis Token | `redis`（默认） | `RedisUserTokenServiceImpl` | Token 存储在 Redis 中，UUID 随机生成，支持主动失效 |
| JWT Token | `jwt` | `JwtUserTokenServiceImpl` | 基于 HMAC-SHA512 签名，无状态，不支持主动失效 |

**Token 创建流程（Redis方式）：**
1. 生成 UUID 作为 Token
2. 将用户信息（id、nickName、dataType、userType、dataList、deptCode）序列化为 JSON 存入 Redis
3. Key: `user:token:{token}`，过期时间由 `application.manage.token.expire` 配置（默认7200秒/2小时）
4. 维护 userId → token 的映射关系，新登录时清除旧 Token（单设备登录）

**Token 创建流程（JWT方式）：**
1. 将用户信息写入 JWT Claims
2. 使用 HMAC-SHA512 算法签名，密钥为 `application.manage.token.jwt-secret`
3. 设置过期时间
4. 退出登录时仅清除权限缓存，Token 本身无法主动失效

### 5.2 Token 前缀

Token 前缀默认为 `Bearer `，配置项：`application.manage.token.token-prefix`

前端请求时需在 Header 中携带：
```
Authorization: Bearer {token}
```

### 5.3 认证过滤器 AuthFilter

**注册位置：** [ManageMvcConfig.java](file:///D:/IdeaProjects/base-project/application/manage-server/src/main/java/com/eghm/app/manage/configuration/ManageMvcConfig.java)

**拦截路径：** `/manage/**`

**处理逻辑：**
1. 从请求 Header 中获取 Token
2. 去除前缀后调用 `userTokenService.parseToken()` 解析
3. 解析成功：将 `UserToken` 设置到 `SecurityHolder`（TransmittableThreadLocal），放行请求
4. 解析失败：返回 `LOGIN_TIMEOUT(8848)` 错误

**白名单：** 通过 `application.manage.white-list` 配置不需要认证的 URL

### 5.4 SecurityHolder 上下文

基于 `TransmittableThreadLocal` 实现，支持异步线程传递用户信息。

| 方法 | 说明 |
|------|------|
| `setToken(UserToken)` | 设置当前登录用户信息 |
| `getUser()` | 获取当前用户信息（可能为null） |
| `getUserRequired()` | 获取当前用户信息（为null时抛 LOGIN_TIMEOUT 异常） |
| `getUserId()` | 获取当前用户ID |
| `remove()` | 清除线程变量 |

### 5.5 权限拦截器 PermInterceptor

- 拦截路径：`/manage/**`（排除白名单）
- 标注 `@SkipPerm` 的接口跳过权限校验
- 维护 URL → 权限编码的映射表（基于 `SysMenu.subPath`）
- 从缓存中获取当前用户的权限列表进行匹配

### 5.6 锁屏拦截器 LockScreenInterceptor

- 检查当前用户是否存在锁屏状态缓存（`lock:screen:{userId}`）
- 存在则返回 `LOCK_SCREEN(1024)` 错误
- 标注 `@SkipPerm` 的接口跳过锁屏校验

## 6. 登录安全防护

### 6.1 安全策略配置

配置前缀：`application.manage.login-security`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| enabled | true | 是否启用登录安全策略 |
| accountMaxError | 5 | 账号最大登录错误次数 |
| accountLockMinutes | 10 | 账号锁定时长（分钟） |
| ipMaxError | 20 | 同一IP最大登录错误次数 |
| ipLockMinutes | 30 | IP锁定时长（分钟） |
| ipLockEnabled | true | 是否启用IP级别锁定 |
| geoCheckEnabled | true | 是否启用异地登录检测 |
| notifyOnLock | true | 账号/IP锁定时是否发送告警 |
| notifyOnGeoChange | true | 异地登录时是否发送告警 |

### 6.2 账号锁定机制

**Redis Key 设计：**
- 错误计数：`login:security:account:error:{account}`
- 锁定标记：`login:security:account:lock:{account}`

**流程：**
1. 登录前检查账号是否被锁定（锁定标记存在 或 错误次数 ≥ accountMaxError）
2. 密码错误时递增错误计数，达到阈值时自动锁定
3. 锁定后设置锁定标记并清除错误计数
4. 登录成功后清除错误计数和锁定标记

### 6.3 IP 锁定机制

**Redis Key 设计：**
- 错误计数：`login:security:ip:error:{ip}`
- 锁定标记：`login:security:ip:lock:{ip}`

**流程：**
1. 登录前检查 IP 是否被锁定
2. 密码错误时递增 IP 错误计数
3. 错误次数达到 `ipMaxError` 的 50% 时，发布 **暴力破解嫌疑告警**（仅告警不锁定）
4. 错误次数达到 `ipMaxError` 时，锁定 IP

### 6.4 异地登录检测

**Redis Key 设计：**
- 历史IP：`login:geo:history:{userId}`（过期90天）
- 历史地域：`login:geo:region:{userId}`（过期90天）

**判断逻辑：**

| 场景 | 处理 |
|------|------|
| 首次登录（无历史IP） | 记录当前IP/地域，允许登录 |
| 同一IP登录 | 允许登录 |
| IP变化但地域相同 | 记录新IP/地域，允许登录 |
| IP变化且地域不同 | **阻断登录**，抛出 `LOGIN_GEO_CHANGED` 异常，发布异地登录告警 |

地域信息基于离线 IP 库解析（`IpRegionUtil.getRegion()`）。

### 6.5 安全事件与告警

**事件类型：**

| 类型 | 枚举值 | 触发条件 | 告警开关 |
|------|--------|----------|----------|
| 账号锁定 | ACCOUNT_LOCKED | 错误次数 ≥ accountMaxError | notifyOnLock |
| IP锁定 | IP_LOCKED | IP错误次数 ≥ ipMaxError | notifyOnLock |
| 异地登录 | GEO_CHANGED | 登录地域发生变化 | notifyOnGeoChange |
| 暴力破解嫌疑 | BRUTE_FORCE_SUSPECT | IP错误次数达到阈值的50% | 始终告警 |

事件通过 Spring `ApplicationEventPublisher` 发布，由 `LoginSecurityEventListener` 异步监听处理，调用 `AlarmService.sendMsg()` 发送告警通知。

## 7. 密码安全

### 7.1 RSA 加密传输

前端登录时密码经 RSA 加密后传输，后端通过 `RsaPasswordDeserializer` 自动解密：

**加密格式：** `RSA(明文密码|时间戳)`

**解密流程：**
1. 使用私钥 RSA 解密，得到 `明文密码|时间戳`
2. 校验时间戳与服务器时间差是否在允许范围内（防重放攻击）
3. 返回明文密码

**配置项：**
- `application.private-key`：RSA 私钥
- `application.public-key`：RSA 公钥

### 7.2 密码存储

- 数据库存储 BCrypt 加密后的密码
- 登录校验时：`encoder.match(SHA256(明文密码), 数据库密码)`
- 初始密码为手机号后8位的 SHA256 值再 BCrypt 加密

### 7.3 密码状态检测

LoginResponse 中返回两个密码状态标识：
- `init`：是否为初始密码（`initPwd == pwd`）
- `expire`：密码是否过期（`pwdUpdateTime + 90天 < now`）

## 8. 登录方式配置

配置项：`application.manage.login-types`

支持多种登录方式组合（List 类型）：

| 枚举 | 值 | 说明 |
|------|-----|------|
| PASSWORD | 1 | 账号密码登录 |
| SMS | 2 | 短信验证码登录 |
| QRCODE | 4 | 扫码登录（暂未实现） |

**示例配置：**
```yaml
application:
  manage:
    login-types:
      - PASSWORD    # 启用密码登录
      - SMS         # 启用短信登录
```

未启用的登录方式会抛出对应异常：`PWD_NOT_SUPPORTED` 或 `SMS_NOT_SUPPORTED`。

## 9. 图形验证码

**校验逻辑：**
- 开发环境（DEV）和测试环境（TEST）**跳过验证码校验**
- 生产环境：从 Redis 获取 Session 对应的验证码（Key: `captcha:key:{sessionId}`）
- 验证码使用后立即删除（一次性）
- 校验不区分大小写

## 10. 接口限流

登录接口使用 `@RateLimiter` 注解实现限流：

```java
@RateLimiter(value = "login", limit = 20, scope = RateLimiter.Scope.IP)
```

| 参数 | 值 | 说明 |
|------|-----|------|
| value | "login" | 限流器名称 |
| limit | 20 | 时间窗口内最大访问次数 |
| scope | IP | 按客户端IP限流 |

超过限流阈值返回 `TOO_MANY_REQUESTS(429)`。

## 12. 错误码汇总

| 错误码 | 枚举 | 说明 |
|--------|------|------|
| 8848 | LOGIN_TIMEOUT | 登录已过期，需重新登录 |

| 1025 | PWD_DECODE_ERROR | RSA密码解密失败或已过期 |
| 429 | TOO_MANY_REQUESTS | 请求过于频繁（限流） |
| - | IMAGE_CODE_ERROR | 图形验证码错误 |
| - | PWD_NOT_SUPPORTED | 密码登录方式未开启 |
| - | SMS_NOT_SUPPORTED | 短信登录方式未开启 |
| - | ACCOUNT_PASSWORD_ERROR | 账号或密码错误 |
| - | USER_LOCKED_ERROR | 用户已被管理员锁定 |
| - | USER_ERROR_LOCK | 用户因多次错误被安全锁定 |
| - | IP_LOGIN_LOCKED | IP因多次错误被锁定 |
| - | LOGIN_GEO_CHANGED | 检测到异地登录 |
| - | TOTP_SN_ERROR | TOTP验证码错误 |

## 14. 配置参考

```yaml
application:
  # 运行环境 DEV/TEST/UAT/PROD
  env: PROD
  
  # RSA密钥对
  private-key: "MIIEvgIBADANBg..."
  public-key: "MIIBIjANBgk..."
  
  manage:
    # Token配置
    token:
      token-type: redis          # redis 或 jwt
      token-prefix: "Bearer "    # Token前缀
      expire: 7200               # 过期时间（秒）
      jwt-secret: "your-secret"  # JWT签名密钥（jwt模式必填）
    
    # 不需要认证的URL白名单
    white-list:
      - /manage/login
      - /manage/smsLogin
      - /manage/sendSms
      - /manage/captcha
    
    # 登录方式
    login-types:
      - PASSWORD
      - SMS
    
    # 登录安全配置
    login-security:
      enabled: true              # 启用安全策略
      account-max-error: 5       # 账号最大错误次数
      account-lock-minutes: 10   # 账号锁定时长(分钟)
      ip-max-error: 20           # IP最大错误次数
      ip-lock-minutes: 30        # IP锁定时长(分钟)
      ip-lock-enabled: true      # 启用IP锁定
      geo-check-enabled: true    # 启用异地登录检测
      notify-on-lock: true       # 锁定时发送告警
      notify-on-geo-change: true # 异地登录时发送告警
```
